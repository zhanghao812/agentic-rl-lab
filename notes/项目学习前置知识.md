# Agentic-RL Lab 项目学习前置知识

本文根据仓库 README、依赖配置与实验代码整理，帮助你从最小 GRPO 实现读到多轮 Agent。各实验的实现存在差异，不要把某个 demo 当作论文的完整实现。

## 1. 项目在做什么

这是实验教程集合，而不是统一训练框架。本地代码组织数据、提示、奖励、损失和训练循环，PyTRIO 提供远程训练与采样接口，SwanLab 记录指标。不同目录中的同名模块服务于各自实验，应按对应 start.md 运行。

共同的数据流是：题目 → 聊天模板 → 采样回答或交互轨迹 → 奖励或教师评分 → 优势或蒸馏目标 → 训练样本 → 前向与反向计算 → 优化器更新 → 保存权重与评测。

## 3. 先看懂这些 Python 写法

- dataclass 自动生成初始化等方法；类型标注通常不会自动检查运行时数据类型。
- tokens[:-1] 去掉最后一个 token。tokens[-n:] 取末尾 n 个，但 n=0 时会取整个列表。
- zip 的 strict=True 检查输入等长，避免训练字段静默错位。
- 闭包让损失回调保存外层的旧策略概率、优势和裁剪阈值。
- Future.result() 等待任务完成；await 等待异步结果并让出事件循环。任务已提交不代表已完成。
- try/finally 保证执行收尾逻辑，不代表异常被忽略。

## 4. LLM 与训练张量

模型根据上下文预测下一个 token。token 不一定等于一个汉字或单词。logprobs 保存的是特定 token 的对数概率，不等于拿到了整个词表分布。序列概率是各位置条件概率的乘积，对数概率则相加。

temperature 与 top_p 控制采样分布；max_tokens 是上限。聊天模板决定角色、工具、视觉和结束标记，改动空白也可能改变实际输入。

### 输入和目标为什么错一位

设提示为 [p0, p1, p2]，回答为 [a0, a1]：

| 字段 | 内容 |
| --- | --- |
| 输入 | [p0, p1, p2, a0] |
| 实际下一 token | [p1, p2, a0, a1] |
| 同步 demo 的目标 | [0, 0, a0, a1] |
| 同步 demo 的优势 | [0, 0, A, A] |

提示内部位置不训练，目标用零占位；真正屏蔽策略损失的是零优势，不是 token ID 0 本身。最后一个提示 token 预测第一个回答 token。各训练字段必须对齐、等长。

### 梯度、detach 与 LoRA

PyTorch 沿计算图自动求导。detach 切断特定路径的梯度；item 提取 Python 标量，常用于日志。不要把需要求导的目标提前转成普通数字。

LoRA 用低秩矩阵增量适配模型，可写作 ΔW=BA。rank 控制增量容量的一部分，越大不保证越好。Adam 使用梯度的一阶、二阶动量更新参数，学习率和 beta 参数控制更新行为。

## 5. GRPO 的最小数学基础

策略是根据上下文生成动作的概率分布。LLM 可以把 token 看成动作，多轮环境也会按一次工具调用讨论动作。rollout 是生成的回答或交互轨迹。reward 表示评分，advantage 表示相对基线的好坏，两者不能混用。

同题四条回答的奖励为 [1, 0, 1, 0]，均值为 0.5，中心化优势就是 [0.5, -0.5, 0.5, -0.5]。全对或全错时优势全零，没有组内相对学习信号，同步 demo 会跳过该组。

同步 demo 使用 A_i = r_i - mean(r)，没有除以标准差。其他变体可能不同，阅读时直接核对优势构造函数。

### 为什么需要旧策略概率

采样时保存旧策略对每个回答 token 的 logprob，训练前向得到当前策略对同一 token 的 logprob：

    ratio = exp(logp_current - logp_sampling)

这是新旧策略概率之比，不是两个答案正确率之比。因此权重版本、上下文和 token 对齐都很重要。

### 损失阅读重点

- importance_sampling：理解概率比如何加权优势，内置接口的具体实现约定不能仅从名称推断。
- PPO：理解概率比裁剪及正负优势下的目标分支，裁剪目标不等于硬限制最终模型概率。
- CISPO：本地实现裁剪 ratio 后 detach，把它作为固定权重乘以当前 logprob 和优势，梯度沿当前 logprob 传播。

同步 demo 的 CISPO 返回损失总和；日志 loss_mean 才除以位置数。显示均值不代表实际优化的目标也取了相同均值。

阅读：[损失说明](../experiments/loss-functions/readme.md)、[同步 GRPO](../experiments/grpo/01-demo-sync.py)、[GRPO 说明](../experiments/grpo/readme.md)。

| ReTool | 代码执行、超时、工具输出和执行轨迹 |
| ALFWorld | 环境状态、动作、终止条件、任务成功率 |

| Vision GRPO | 图片预处理、多模态输入和视觉 token |

KL(P || Q) 和 KL(Q || P) 不相同。读蒸馏代码要明确：谁采样、谁提供概率、谁被更新。沿采样轨迹打分也不等于直接计算每个位置的全词表 KL。

多轮 Agent 要区分模型动作和环境观察。工具返回的文本不是模型生成的动作，需检查对应训练掩码，避免错误训练模型模仿环境输出。

## 7. 如何解释指标

- reward：检查奖励范围、答案解析和格式要求，格式错误也可能导致零分。
- frac_degenerate：组内奖励完全相同的题目比例；偏高可能是太容易或太难，要结合 reward 判断。
- train_tokens：核对统计所有回答位置还是非零优势位置；同步 demo 使用后者。
- 生成长度：变长不一定代表能力提高，也可能增加成本或截断。
- loss：不同算法和归一化方式之间不能直接比较绝对数值。
- 独立评测：保持题目集、采样次数、评分规则可比，区分训练奖励和测试能力。
- 随机性：本地 NumPy seed 不会自动控制远程采样的全部随机性。

## 8. 建议学习顺序

1. 读 [环境配置](../experiments/getting-started/readme.md) 和 [依赖配置](../pyproject.toml)。仓库声明 Python >=3.13，实际版本约束以该文件为准。
2. 补 Python、概率与张量基础，能解释 RolloutSample 的字段。
3. 阅读同步 GRPO：配置 → prompt → rollout → 评分 → 优势 → Datum → 损失 → 更新 → 日志。
4. 手算混合正确、全对、全错三种组优势，画出输入目标对齐。
5. 对照异步 GRPO，标出任务提交、等待、参数更新和下轮采样的顺序。
6. 比较 GSPO 与 DAPO 的概率比、裁剪对象和归一化分母。
7. 在蒸馏和工具 Agent 中选一个方向深入，再扩展视觉等任务。

自测：能否说明哪些 token 参与训练、旧 logprob 从哪里来、哪个张量保留梯度、一次参数更新发生在何时？能回答这些问题，就已经抓住主流程。
